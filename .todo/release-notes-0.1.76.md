# Hermes UI v0.1.76

本次是一个**稳定性修复版**：主线是修掉「回合早已结束、界面却永远显示生成中」这个僵尸态，并给会话菜单加一个手动出口。

> 说明：v0.1.75 之后到本版之间的改动全部包含在本说明里（中间没有单独的 Release）。

---

## 修复

- **界面永久卡「生成中 · 已工作 MM:SS」（服务端其实早已收尾）**：本次最要紧的一条。表现是某个会话一直显示「生成中 ≈24 tps · 已工作 317:40」、几小时不吐新字，但**会话列表里它是正常的**，用手机/网页连同一台服务器看内容早就写完了，只有这个窗口不动，重启应用才好。
  根因在客户端显示态：回合正常结束的那条路径**漏清「本回合已工作多久」的计时**；而结束之后到达的迟到/重放数据包，又会把「正在生成」的气泡重新建出来。更麻烦的是这一组合恰好落在所有自动恢复逻辑的**判定范围之外**，于是谁也救不了它。现在：收尾时把计时与残留缓冲一次清干净；回合结束之后到达的迟到数据包一律丢弃；万一还有别的入口把气泡建出来，1 秒一次的看门狗会在 20 秒内清掉它并重新拉一次服务端内容。
- **中文名附件打不开（404）**：附件名带中文（或空格、特殊符号）时，下载链接会被二次编码、指向不存在的路径。现在链接目标只编码一次并规整路径形态，中文名附件可以正常打开。
- **附件/音频/视频链接前面的 emoji 换成矢量图标**：链接文案因此恒等于真实文件名；顺带**下载下来的文件名不再带装饰性 emoji / 符号**（此前会落到 `Downloads/📎 spec.pdf` 这种名字）。

## 新增

- **会话菜单新增「强制刷新」**：位于会话右上角「⋯」菜单的第一组，紧随「归档」。遇到界面落后于服务端、卡在生成中一类显示问题时点它即可——它会把本地显示状态与服务端对齐、并重新拉取本会话内容。**纯读取操作**：不改动会话内容；若此刻真有回合在跑，它会改走状态查询，不会打断。

## 平台

- 本机发布为 Android（arm64）与 Windows x64 安装包；Linux tar.gz 与 macOS zip 由 CI 产出。

---

**文件**
- Android：`HermesUI-0.1.76-arm64-app-release.apk`（arm64，适配小米 14 等现代机型）
- Windows：`HermesUI-0.1.76-x64-setup.exe`

**升级方式**：手机装新版 APK；Windows 直接跑安装包覆盖安装（数据不动）。

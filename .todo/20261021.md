## [已收口] fix(chat): interim 整段指纹去重 —— 防「同一句话重复 N 遍」

- **提交**：`7955466`（分支 `fix/interim-fingerprint-dedupe`，基线 `ef6d455`）
- **范围**：`lib/features/chat/chat_controller.dart`（+100）、`test/features/chat/interim_fingerprint_dedupe_test.dart`（新增 5 例），共 389 行新增、1 行删除。

### 现象

主人真机 2026-10-20 21:40 截图：两段互不相干的会话里，同一段正文分别重复 **4 遍 / 2 遍**，界面上呈「同句 + 空行」的多段形态。

### 定性（三重物证，缺一不可）

1. **存储层单份**：`state.db` 里两段话**各只有一条**；`count(*) == count(DISTINCT content)`（101/101、50/50）⇒ 重复 100% 在渲染层（非生成 / 非线程 / 非网络）。
2. **服务端会话 JSON 也单份**：`webui_30002/sessions/<sid>.json` 的 `messages[]` 里同句只在 `idx=84` 出现一次（`finish_reason=tool_calls`）⇒ 服务端组装亦无重复。
3. **客户端 SSE 日志（决定性）**：`%USERPROFILE%\Documents\hermes_cache.sqlite` → `diagnostics_logs`（`tag='sse'`）里，实机那刻的序列是
   `token: "\n\n评测在跑（要编码 8284 条语料 × "` → `token: "3 轮）。本喵等结果喵。"` → `interim_assistant: alreadyStreamed=true "评测在跑…"`
   —— **同一段 interim 只到达 1 次**；本机 21:00–21:45 共 22 条 interim **全部 `alreadyStreamed=true`** ⇒ 客户端按设计全部忽略。

### 机制（服务端脆弱点 + 客户端启发式失效）

- 服务端 `already_streamed` 靠 `_is_visible_output_echo`（webui `api/streaming.py`）判定 —— 判据是「已流出正文（`STREAM_PARTIAL_TEXT`，**仅 token 路径累积**）的**尾部**是否 endsWith 本段」。
  **手机弱网（截图右上角 VPN + 5G）下 token 帧丢失 ⇒ 尾部不匹配 ⇒ 标记失效 ⇒ interim 整段被当「新段落」再次追加** ⇒ 每次重投/重连多一份 ⇒ 重复次数不等（4 遍 / 2 遍），与「重连次数」吻合。
- 客户端既有三道启发式闸门（尾部匹配 / 整段包含 / ≥2 字重叠）都是「相对当前 content 的关系」—— live 气泡换锚后 content 里已无该段 ⇒ 全数失效。

### 修法（**仅客户端**，不动服务端）

- `_deliveredInterimFingerprints`（单回合，整段归一化指纹集）—— 位置无关的确定性判据，不再依赖游标 / 位置。
- `_tokenStreamedText`（**仅 token 路径**累计的正文）—— 判「这段 interim 是否已被 token 流出过」；**刻意不用整个 streaming content**（那里也含 interim 自己贡献的段落 ⇒ 模型在两个工具轮次重复同一句话这类合法重复会被误吞）。
- `_handleInterimAssistant` 入口加闸门：**已投递过** ∧（`isReplayConnection` ∨ **已被 token 流出过**）⇒ 直接吞掉；否则照常走旧路径（保护合法重复）。
- 命中时写 `chat_apply` WARN 诊断日志（正文摘要 + `replay` / `afterSeq` / `matchedPrefix`）⇒ **下次真机再遇到，App 诊断页可直接判定重复来源**，不必再挖。
- 指纹集与 `_tokenStreamedText` 均在 `_beginStream`（新回合）清空。

### 诚实声明（重要）

本轮在**当前源码上以 5 种场景**（live 重投 / `fullReconnect` 全量回放（`replayAfterSeq=0`）/ 工具卡夹在中间 / 游标错位 / 跨回合）**均复现不出重复**，且**关掉新闸门测试依然全绿** ⇒ 该闸门在当前源码上**无鉴别力**，定位为 **防御性加固**（打在已证实的脆弱点上，零风险），**不声称「治好了该现象」**；真机触发条件仍需手机端特有状态（真后台 / 锁屏、网络切换、App 被系统挂起后恢复）复现后再定论。
